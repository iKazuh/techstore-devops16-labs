# 🗺️ Guia de Contribuição - TechStore DevOps

Olá, equipes! Para garantir a organização do nosso repositório e o sucesso nas apresentações do projeto, adotamos uma estrutura de documentação descentralizada. 

Cada squad é responsável por manter a documentação técnica da sua respectiva pasta atualizada.

---

## 📝 O que fazer?

A equipe de **Documentação** já criou os arquivos base (templates) dentro das pastas de desenvolvimento. Cada equipe deve acessar o seu respectivo arquivo e preencher os dados técnicos:

*   **SQUAD BACKEND:** Deve preencher o arquivo `backend/README.md` detalhando as rotas da API, dependências e variáveis de ambiente necessárias.
*   **SQUAD FRONTEND:** Deve preencher o arquivo `frontend/README.md` explicando o funcionamento da interface, como rodar o servidor visual e como conectar com a API do backend.

---

## 🛠️ Padrão de Commits (Conventional Commits)

Como estamos em uma disciplina de DevOps, rastreabilidade é fundamental. Solicitamos que todos utilizem prefixos nos commits para identificar o tipo de alteração:

*   `feat:` Criação de novas funcionalidades (ex: `feat: adiciona criptografia no login`)
*   `fix:` Correção de bugs ou problemas no código (ex: `fix: corrige porta de conexao`)
*   `docs:` Alterações exclusivas na documentação (ex: `docs: atualiza rotas no readme`)
*   `ci:` Alterações em arquivos de pipeline/esteira (ex: `ci: ajusta configuracao do gitlab-ci`)
